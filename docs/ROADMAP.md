# План разработки

Дата исходного плана: 2026-10-18.

Каждая задача содержит способ реализации и наблюдаемый критерий готовности. Выполнять по порядку, небольшими связанными группами. Фактический прогресс и ближайший ID вести в STATUS.md. Незакрытые критерии проверки не отмечать выполненными только по наличию кода.

Числа и названия промежуточные. В начале нет финальных моделей, частиц и сложного оформления. Простые подсказки, индикаторы попадания и читаемые границы нужны сразу для проверки механик.

Уточнение 2026-10-19: целевые механики находятся в [AI_GAME_SPEC](AI_GAME_SPEC.md). T001–T090 сохраняют ID; новые требования добавлены подзадачами. Закрытые T032–T035 описывают прежний проверенный объём, а не весь новый документ. T032a/T034a реализованы после T036. Основа T038 реализована: станция 1–3, инструменты и рюкзак. T039 и первый вариант T040 реализованы. T040a реализован. T040e и T039a реализованы, ближайший код T041 (первый волк), свободное размещение T040d ждёт T042; зависимые боевые/строительные рецепты T038a подключаются после T040/T043/T044. Весь T038 остаётся открытым до их проверки; далее враги и первый срез. Поздние машины, полный каталог классов и платежи не блокируют первый срез T049.

Дополнение 2026-10-19: [COMPANION_AI](COMPANION_AI.md) задаёт напарников новичок/мидл/профи. Добавлены T049a/T055a/T062a/T069a/T078a/T080b. ## Этап 0. Запускаемый каркас — T001–T005

- [x] **T001. Инициализировать проект.** Создать npm workspaces, apps/client, TypeScript, Vite и Vue 3; проверить совместимые версии, зафиксировать lock-файл. **Готово:** чистая установка и сборка пустого приложения проходят; README содержит реальные команды.
- [x] **T002. Встроить Three.js.** Создать canvas, сцену, камеру, renderer, изменение размера и обработку ошибки WebGL. **Готово:** видна тестовая сцена, окно корректно меняет размер.
- [x] **T003. Выделить игровую сессию.** Минимальные Game, LocalSession, ID сущностей, команды и снимок состояния; без реализации сетевого транспорта. **Готово:** UI запускает и завершает LocalSession, не управляя мешами напрямую.
- [x] **T004. Подключить коллизии.** Rapier, фиксированный шаг, пол, несколько стен, капсула игрока и debug-показ коллайдеров. **Готово:** тело не проходит сквозь пол/стены, симуляция не ускоряется с FPS.
- [x] **T005. Сделать тестовую поляну.** Примитивный персонаж, несколько деревьев-заглушек, старт/повтор, очистка ресурсов. **Готово:** можно несколько раз запустить и закрыть сцену без второго цикла и лишних обработчиков.

**Состояние этапа:** T001–T005 реализованы; базовая браузерная проверка T002/T005 выполнена 2026-10-18 (см. STATUS.md). Оставшиеся ограничения окружения перечислены в TESTING.md.

**Промежуточный результат:** запускаемый каркас; игровые действия ещё не считаются готовыми.

## Этап 1. Персонаж и Roblox-подобная камера — T006–T014

- [x] **T006. Создать InputActions.** Move, Look, Jump, Sprint, CameraLock, Primary, Interact, Hotbar, Inventory; контексты Gameplay/UI. **Готово:** действия читаются независимо от конкретных клавиш; меню блокирует игровой ввод.
- [x] **T007. Передвижение.** WASD относительно камеры, нормализация диагонали, плавный разворот персонажа. **Готово:** одинаковая скорость по прямой и диагонали; поворот камеры меняет направление движения.
- [x] **T008. Гравитация и прыжок.** Проверка земли, вертикальная скорость, склоны/ступени. **Готово:** прыжок доступен с земли, приземление устойчиво, стену не перелезают спамом прыжка.
- [x] **T009. Третье лицо.** Следование камеры, ПКМ-обзор, ограничение вертикали, колесо дистанции. **Готово:** камера вращается плавно, стоящий персонаж не обязан поворачиваться вслед за ней.
- [x] **T010. Коллизия камеры.** Проверка препятствий от точки слежения до желаемой позиции. **Готово:** стена не закрывает игрока и камера не уходит за неё.
- [ ] **T011. Shift-lock и первое лицо.** Отдельное действие фиксации направления, Pointer Lock после клика, скрытие мешей у камеры. **Готово:** оба режима работают и Esc возвращает курсор; отказ Pointer Lock обработан.
- [x] **T012. Бег и настройки ввода.** Ctrl для бега, отдельная чувствительность, инверсия Y, локальное сохранение настроек. **Готово:** Shift не запускает бег, раскладка согласована с CONTROLS.
- [ ] **T013. Сенсорное управление.** Стик, область обзора, прыжок и действия, мультитач, touch-cancel. **Готово:** можно одновременно идти, смотреть и прыгать; UI не крутит камеру.
- [ ] **T014. Проверить управление целиком.** Потеря фокуса, открытие меню, низкий FPS, изменение окна, мобильная раскладка. **Готово:** нет залипания клавиш и перемещения в текстовом поле; ограничения проверки записаны.

**Состояние этапа:** код T006–T014 реализован. T009 проверен в браузере 2026-10-18; T011/T013/T014 остаются открыты по Pointer Lock и реальному телефону. 2026-10-19 исправлена комбинация ПКМ + ЛКМ, автоматический сценарий проходит; повторная проверка в браузере добавлена в T014.

По указанию пользователя от 2026-10-18 ручная проверка не блокирует следующий блок T015–T024.

**Промежуточный результат:** управляемый персонаж на полигоне.

## Этап 2. Удары и сбор ресурсов — T015–T024

- [x] **T015. Активный предмет.** Определение инструмента, слот руки и простая модель топора. **Готово:** применение зависит от выбранного предмета; пустая рука не рубит дерево.
- [x] **T016. Цикл удара.** Подготовка → попадание → восстановление; cooldown в конфиге. **Готово:** спам ЛКМ не увеличивает частоту и не создаёт параллельные атаки.
- [x] **T017. Поиск попадания.** Сектор/shape query перед персонажем, дистанция и видимость. **Готово:** цель сзади или за стеной не получает удар.
- [x] **T018. Общая обработка воздействия.** DamageInfo и получатели для манекена и ресурсного объекта. **Готово:** один удар повреждает каждую разрешённую цель не более одного раза.
- [x] **T019. Минимальная обратная связь.** Взмах без финальной анимации, краткая индикация попадания и HP манекена. **Готово:** видно момент и результат удара.
- [x] **T020. Наведение взаимодействия.** Выбор доступной цели, подсветка и текст действия E. **Готово:** дальняя цель и цель за препятствием не выбираются.
- [x] **T021. Рубка дерева.** Запас ресурса, подходящий инструмент, истощение и отключение коллизии. **Готово:** после нужного числа ударов дерево исчерпывается один раз.
- [x] **T022. Предмет в мире.** Создать древесину с уникальным ID и простым отображением; без дорогой физики каждого бревна. **Готово:** из одного дерева появляется ровно заданное количество.
- [x] **T023. Подбор.** E отправляет команду LocalSession; минимальный контейнер ресурсов и HUD количества. **Готово:** предмет исчезает только после успешного зачисления; повтор команды не выдаёт его снова.
- [x] **T024. Проверить первую игровую цепочку.** Подойти → ударить → срубить → подобрать → повторить. **Готово:** цепочка работает на ПК и доступном touch-сценарии; есть проверки повторного попадания и повторной выдачи.

**Состояние этапа:** T015–T024 реализованы; T019/T024 закрыты после браузерной проверки ПК и touch-эмуляции 2026-10-18. Настоящий телефон проверяется в T013/T014. См. STATUS.md и TESTING.md.

**Первый игровой прототип:** передвижение, удары и добыча древесины; проверен на ПК и в touch-эмуляции; реальный телефон остаётся в ручном сценарии.
